名NFC 電子名片開啟設定工具 ↗

GETTING STARTED / V1.0

從一張名片，開始聯繫。

第一個案例：台茂當舖・羅經理。這一版提供手機名片、儲存聯絡人、電話、LINE、官網、社群、分享網址，以及可擴充的公司與名片設定。

目前資料狀態

只填入已提供的公司名稱、顯示姓名與官網。電話、LINE、Email、地址、社群與官方 Logo 保留空白；空白項目不會出現可誤撥的連結。實體 NFC 卡尚未寫入，也尚未做實機感應驗證。

1. 先測試名片

  1. 使用手機瀏覽器開啟 羅經理電子名片。
  2. 點「官方網站」，確認導向台茂網站。
  3. 點「儲存到手機聯絡人」。瀏覽器會開啟或下載 .vcf；在手機預覽中選「建立新聯絡人」或「加入現有聯絡人」。若僅下載，從「檔案」或「下載」開啟該檔案。
  4. 點「分享名片」可複製固定網址；支援的手機也可叫出系統分享選單。

名片頁不會自動取得訪客的通訊錄。儲存聯絡人需要訪客自行確認。尚未設定電話時，儲存內容只有姓名、公司、介紹與官網等已知資料。

2. 設定公司與聯絡方式

  1. 開啟 名片設定工具，載入台茂已發布資料。
  2. 填入本人確認的電話、LINE 完整連結與其他公開資料，可上傳 Logo。
  3. 即時預覽只影響目前畫面。可儲存本機草稿；請另外「下載公司設定 JSON」備份。
  4. 管理者將 JSON 放入原始碼的 tenants/taimao.json，執行 npm run build 並部署產生的 dist/。
  5. 部署成功後重新整理公開名片，確認電話、LINE、Logo 與下載的聯絡資料均已更新。

設定工具不是登入後台。沒有伺服器寫入或跨公司編輯 API，訪客無法藉此發布修改。本機草稿依公司代碼及名片代碼分開保存；同一瀏覽器上的其他人仍可能存取本機資料。只存準備公開的資訊。

3. 擴充給其他公司

選「建立新公司」，填獨立公司代碼，例如 company-b；名片代碼例如 amy。匯出後新增 tenants/company-b.json，重新建置。

公司設定檔名片網址路徑
台茂當舖tenants/taimao.jsonc/taimao/luo/
其他公司（示例，未發布）tenants/company-b.jsonc/company-b/amy/

同一家公司可用「新增這家公司的名片」加入多名員工。每張名片只載入自己的公開資料，不會以不存在的公司網址回退到台茂資料。匯出檔保留該公司的全部名片；部署前由管理者確認公司代碼不與現有公司衝突。

第一版是公開資料檔與網址分隔，不提供公司帳號、私密資料或伺服器層級的租戶授權。不同公司檔案仍屬公開資源；若需要各公司登入自行管理，後續需增加登入、後端 tenant_id 權限檢查、資料庫隔離、稽核與備份。不可將客戶借款資料或密鑰放入 JSON。

4. NFC 卡片寫入教學

名片接收者不需要安裝專用 App；寫卡的人需要支援 NFC 寫入的手機與工具。請準備可寫入 NDEF 網址的 NFC 卡，常見 NTAG213 / 215 / 216 類型可供選擇，並依卡商確認手機相容性。不要使用門禁卡或金融卡。

  1. 先用另一支手機的瀏覽器確認公開名片網址能開啟，且不要求登入。
  2. 寫卡手機安裝開發者 wakdev 的 NFC Tools。
  3. 開啟 NFC Tools → Write（寫入） → Add a record（新增紀錄） → URL / URI。
  4. 貼上完整 https:// 名片網址。請檢查 App 沒有重複加入 https://https://。保留一筆網址紀錄，不要寫入 JSON、聯絡資料檔或設定工具網址。
  5. 按 Validate / OK → Write，將卡片靠近手機 NFC 感應區，等候成功訊息。
  6. 離開寫卡 App，以另一支手機靠近卡片測試。iPhone 通常會顯示網站通知，點通知後才開啟；Android 行為依機型、NFC 設定與瀏覽器而異。

羅經理預定使用的固定網址：

https://gucci3364-spec.github.io/neihupawnshop/nfc/c/taimao/luo/

iPhone XS 及後續機型支援背景讀取，通常需螢幕亮起；若重開機尚未解鎖、相機／Apple Pay 使用中或飛航模式等狀況，可能不會讀取。手機上端靠近卡片，Android 感應位置常在背面，依機型調整。讀取 NFC 不等於網站離線可用，開啟網頁仍需網路。

測試期間先不要永久鎖卡。若決定鎖成唯讀，務必先確認網址穩定；部分卡片的唯讀鎖定無法復原。只要名片網址不變，後續改電話、LINE 或 Logo，只需更新網站。

5. GitHub Pages 與部署

技術上，此版本為純 HTML / CSS / JavaScript / JSON / VCF，無需資料庫，支援 GitHub Pages 的子目錄部署。正式商業 SaaS、付費多公司平台與敏感交易不適合使用 GitHub Pages；GitHub 官方條款明確限制此類用途。

目前專案的子目錄方式

建置後將 dist/ 的內容放入 gucci3364-spec/neihupawnshop 的 nfc/ 目錄，沿用現有 Pages 流程。原始碼放 nfc-system/。不要覆蓋網站根目錄首頁，也不要把根目錄 Pages 來源改成其他資料夾。

獨立新專案方式

建置時指定網址，例如：

CARD_BASE_URL=https://帳號.github.io/專案名稱/ npm run build

將 dist 內容放到新專案發布目錄，於 GitHub Settings → Pages 選擇發布分支與目錄。此版本不含自動建置 workflow；修改 JSON 後仍需先建置，再提交產物。正式用自訂網域前，先固定網址並確認 HTTPS。

6. 驗收與限制

  • 網頁預覽與程式測試不能代替 iPhone / Android 實機儲存聯絡人與 NFC 感應測試。
  • 電話、LINE、社群與 Logo 需要本人確認後填入；目前空白按鈕屬預期狀態。
  • 第一版沒有收款、追蹤、訪客資料收集、登入管理或自動發布功能。
  • 頁面暫時標記 noindex，供第一版測試；noindex 不是存取權限控制。
